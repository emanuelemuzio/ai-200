## Self-check questions

### 1. 

An AI document-processing application must run a proprietary converter that depends on native binaries. Which session pool should the developer choose?

A. A custom container session pool with the converter packaged in its image
B. A built-in code interpreter session pool accessed through its REST API
C. A built-in code interpreter session pool accessed through `SessionsPythonREPLTool`

> [!answer]- Reveal answer
>  A: A custom container session pool lets the developer package the proprietary converter and its native binary dependencies directly into the container image.

### 2. 

An application executes untrusted Python that only processes files uploaded by the backend. Which network configuration best limits the risk of data exfiltration?

A. Set `--network-status EgressEnabled` and restrict access through the backend identity
B. Set `--network-status EgressDisabled` on the session pool
C. Increase `--cooldown-period` so the session retains its files

> [!answer]- Reveal answer
> B: `--network-status EgressDisabled` prevents the session from making outbound network connections, reducing the risk of data exfiltration.

### 3. 

A multitenant backend needs to preserve temporary files across related requests without letting users address another tenant's session. How should it manage session identifiers?

A. Use the user's email address as the identifier and include it in client requests
B. The container image is too small to include all required libraries.
C. Accept an identifier generated by the client and validate only its format

> [!answer]- Reveal answer
> C: The server should generate an unpredictable identifier and keep the tenant/user or conversation association in backend state, preventing users from accessing another tenant’s session.

### 4. 

The execution API returns an HTTP success response, but the submitted Python raises an exception. How should the backend classify the outcome?

A. As an execution failure
B. As a transport failure
C. As a successful result

> [!answer]- Reveal answer
> A: The HTTP request can succeed at the transport/API level while the submitted code fails during execution; therefore, it is an execution failure.

### 5.  

A generated-code execution times out at the backend, and the backend can't determine whether the code produced side effects. What is the safest retry policy?

A. Retry every timeout immediately with the same session identifier
B. Retry only when the operation is idempotent and the backend can evaluate the resulting state
C. Retry only with a new session identifier

> [!answer]- Reveal answer
> B: A timeout does not prove that execution failed before producing side effects, so retries are safest only for idempotent operations whose resulting state can be evaluated.
